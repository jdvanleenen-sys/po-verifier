## What the reads got right, observed
- All three read a PO number with no slash as written, and the code took it.
- Tamarack: read "18,84 $" as $18.84, asked Sam about square metres against square feet, and set the
  walls line apart on his answer. The two taxes came out $3.00 and $5.99, each rounded on its own.
- Kestrel: read "500.00 CR" as a credit and saw that comparing 0 against -1 would claim $500 owed;
  asked Sam rather than guess.
- Birchwood: caught the planted mismatch (392 SF written, but 12' x 12' is 384) and asked Sam which.
- Every money figure matched the key in all three houses.

## Found and fixed in this round
1. **A painter's checklist sent as a PDF was taken for a PO** (Birchwood). It was attached whatever
   Sam answered, `--notes yes` stopped with "no notes file", and the numbered record said "notes: no"
   though Sam said yes. A PDF named as notes or a checklist is now notes, attached only on his yes,
   with its file name on every page (`build_request.intake`, `printing.proof_pdf`).
2. **The cold-run copies carried the stand-in painter's notes** (square feet as floor area, a 53-row
   price list), which every agent rightly questioned. `cold_run.py prepare` now writes the style's own.

## Found, not yet fixed
1. **GST and QST cannot print as two amounts.** The request check reads one tax amount per group, so
   the Quebec request prints one combined line. A Quebec builder may want them apart.
2. **Numbers the PO prints its own way** (decimal commas, "CR", no $ sign) must be rewritten as plain
   numbers in the read-back's number columns. The agents did it and named it at risk, but 02 read
   says "copy exactly as printed" and has no rule for it.
3. **Credit lines and other units have no rule.** The grid's "0 measured: the whole line becomes a
   credit" message points the wrong way on a negative PO qty, and compare would call 1800 SF against
   167 m2 "PO quantity short" if the row were compared. Sam set both aside; nothing in setup keeps it.
4. **The job-name check reads only "JOB NAME:".** Kestrel prints "JOB:", Birchwood none. The job line
   is still checked against house-info's address and lot.
5. **The job line must hold every number in house-info's address**, postal code included. The layout
   does not say so; Kestrel failed check 6 once and fixed it.
6. **PO-wide terms have no place in the grid** ("gross wall areas", "quantities are billable maximums,
   approved in writing by the site supervisor"): they apply to every line, and line-notes reads only
   notes under a line.
7. **A measurement that contradicts Sam's own note** (392 against "12' x 12'") is caught only by the
   agent's judgement; no code check looks for it.
8. **A yes given to read-back 1 was written into read-back 2** in all three runs. The folder does not
   say whether a yes carries to the next number.
